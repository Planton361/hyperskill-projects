## Exact original root cause

The generator resolves Git HEAD and stores that revision in projection provenance. The snapshot was generated when HEAD was `4215ac2fefea0ff6084210bac8d2dc0f42c32b34`, then committed in `fb76acb9c1fcca6f43c01d7fffa6eb6a3a1fdf1c`. The later pre-push test reused the earlier artifact after HEAD advanced. Its provenance was accurate when built; the tested artifact was stale.

A generated file committed into the same commit cannot normally contain that commit's own SHA: changing the file changes the SHA. Repeatedly regenerating and committing it would not solve the circular requirement.
